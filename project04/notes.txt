29. CONFIGURE NGINX REVERSE PROXY
============================================================

On Nginx EC2:

sudo nano /etc/nginx/sites-available/default


Add:

------------------------------------------------------------

server {

    listen 80;

    server_name _;

    location / {

        proxy_pass http://10.0.2.151:8080;

        proxy_set_header Host $host;

        proxy_set_header X-Real-IP $remote_addr;

        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_set_header X-Forwarded-Proto $scheme;

    }

}

------------------------------------------------------------


Replace:

10.0.2.10

with actual private IP of Tomcat.

48. INTERVIEW EXPLANATION
============================================================

INTERVIEWER:

Why did you put Nginx in the public subnet?


ANSWER:

I wanted to expose only the reverse proxy to the Internet.
The actual application server is deployed in the private
subnet, so users cannot directly access the application.


INTERVIEWER:

How does Nginx communicate with the private server?


ANSWER:

Nginx communicates with the private Tomcat server using its
private IP address. Both servers are inside the same VPC, so
AWS uses the VPC local route for communication.


INTERVIEWER:

Does the Nginx-to-Tomcat traffic go through NAT Gateway?


ANSWER:

No.

NAT Gateway is not used for communication between the public
and private subnets inside the same VPC.

The traffic uses the VPC local route.


INTERVIEWER:

Why do you need NAT Gateway?


ANSWER:

The private EC2 needs outbound Internet access for activities
such as downloading packages and updates, but it should not
accept inbound connections from the Internet.

NAT Gateway provides this outbound Internet connectivity.


INTERVIEWER:

Can Internet users access Tomcat directly?


ANSWER:

No.

The Tomcat EC2 does not have a public IP and its Security Group
allows port 8080 only from the Nginx Security Group.


INTERVIEWER:

What happens when the user opens the website?


ANSWER:

The request first reaches the public Nginx EC2 through the
Internet Gateway. Nginx then forwards the request to the
private Tomcat server using its private IP. Tomcat processes
the request and sends the response back through Nginx to the
user.
